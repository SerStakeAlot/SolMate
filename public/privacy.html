Privacy Policy

Last updated: January 14, 2026

1. Introduction

SolMate is committed to protecting your privacy. This Privacy Policy explains how we collect, use, and safeguard your information when you use our decentralized chess application on the Solana blockchain.

2. Information We Collect

We collect minimal information necessary to provide our services:

  • Wallet Address: Your public Solana wallet address when you connect to play
  • Game Data: Chess moves, game results, and timestamps
  • Transaction Data: Records of stakes and payouts (publicly visible on blockchain)

We do NOT collect: names, emails, passwords, IP addresses, or personal identification information.

3. How We Use Your Information

Your information is used solely to:

  • Facilitate chess matches and process stakes
  • Display game history and statistics
  • Improve our services and user experience

4. Blockchain Data

SolMate operates on the Solana blockchain. All transactions are:

  • Publicly visible on the blockchain
  • Immutable and cannot be deleted
  • Associated with your wallet address (pseudonymous)

5. Third-Party Services

We integrate with Solana Blockchain for transaction processing and wallet providers like Phantom and Solflare. These services have their own privacy policies.

6. Security Certificate

SolMate implements enterprise-grade security measures to protect our platform and users:

🛡️ Infrastructure Protection

  • Cloudflare CDN & DDoS Protection – All traffic proxied through Cloudflare's global network
  • Web Application Firewall (WAF) – Automated protection against common attacks
  • Bot Management – AI-powered bot detection and mitigation
  • SSL/TLS Encryption – All connections encrypted with TLS 1.2+

🔒 Application Security

  • Rate Limiting – API abuse prevention (100 req/min general, 10 req/min sensitive endpoints)
  • WebSocket Connection Limits – Max 5 connections per IP address
  • Input Validation – Server-side validation of all user inputs
  • Payload Size Limits – Protection against oversized request attacks

🌐 HTTP Security Headers

  • Strict-Transport-Security (HSTS) – Forces HTTPS for 1 year with preload
  • Content-Security-Policy (CSP) – Prevents XSS and injection attacks
  • X-Frame-Options: DENY – Blocks clickjacking attempts
  • X-Content-Type-Options: nosniff – Prevents MIME-type sniffing
  • X-XSS-Protection – Browser XSS filter enabled
  • Referrer-Policy – Controls referrer information leakage
  • Permissions-Policy – Disables camera, microphone, geolocation access

⛓️ Blockchain Security

  • Audited Smart Contract – Escrow program security reviewed
  • PDA-Based Escrow – Funds held in Program Derived Addresses, not admin wallets
  • Immutable On-Chain Logic – Contract code cannot be modified post-deployment
  • Transaction Verification – All payouts verified on-chain before processing

🔐 Authentication & Authorization

  • Wallet Signature Verification – Cryptographic proof of wallet ownership
  • No Password Storage – Authentication via wallet signatures only
  • Session Management – Secure WebSocket session handling
